El problema

Sabemos que el disco está lleno.
No sabemos por qué.

01

Falta de visibilidad

El explorador obliga a revisar carpeta por carpeta. Es lento y no muestra proporciones.

02

Herramientas antiguas

WinDirStat tiene una interfaz desactualizada y puede ser lento en SSD grandes. ncdu es solo terminal.

03

Decisiones inseguras

Sin información clara, el usuario borra a ciegas o no libera espacio por miedo.

Oportunidad: una herramienta moderna, rápida y comprensible para usuarios no técnicos.

La solución

Escanear → Ver → Actuar

DiskMap convierte el uso del disco en un mapa visual interactivo, accesible desde el navegador y sin enviar datos a la nube.

📊 Treemap interactivo 📋 Lista con barras de peso 🌐 Búsqueda global 🎛️ Filtros por categoría, tamaño y antigüedad 🗑️ Papelera y eliminación segura 🔒 Carpetas sin permisos visibles 💻 100% local

Sin instalación pesada

Se abre en Chrome, Edge o Firefox mediante un servidor local liviano.

Sin Internet

D3 está incluido localmente. Nada sale del computador.

Patrones de diseño

Observer para el progreso. Strategy para los filtros.

Observer

Sujeto observable: ScanStateSubject

Observadores: barra de progreso, contador de archivos, resumen, estado del escaneo.

Medio: WebSocket envía eventos status, progress, complete, error.

Agregar un panel nuevo no obliga a tocar el escáner.

Strategy

Contexto: FilterManager

Estrategias: CategoryFilter, SizeFilter, AgeFilter, ExtensionFilter.

Contrato común: matches(file).

Agregar un filtro nuevo no obliga a tocar el gestor.

Ambos patrones reducen acoplamiento y mejoran la mantenibilidad (ISO/IEC 25010).

Base de datos

La decisión actual: estructuras en memoria

DiskMap no usa un DBMS en esta versión porque el análisis es efímero y la fuente de verdad es el sistema de archivos.

¿Por qué?

• Cada escaneo reemplaza al anterior
• Una copia en SQL se desactualiza respecto al disco
• Evita I/O extra y latencia durante el escaneo
• Cero configuración: npm start y listo
• Cumple HU4: todo local, sin servicios externos

¿Qué usa en su lugar?

Modelo propuesto: historial y auditoría con SQLite

SCANS

id, root_path, started_at, finished_at, status, total_files, total_size, skipped_dirs, verified

NODES

id, scan_id, parent_id, name, path, type, size, category, modified_at, locked, depth

FILE_ACTIONS

id, scan_id, node_id, action, performed_at, success, message

SETTINGS

key, value

Tema, última ruta, preferencias.

SCANS 1 ─── N NODES        NODES 1 ─── N NODES (parent_id)
SCANS 1 ─── N FILE_ACTIONS  NODES 1 ─── N FILE_ACTIONS

-- Índices clave
CREATE INDEX idx_nodes_scan_parent ON nodes(scan_id, parent_id);
CREATE INDEX idx_nodes_scan_size   ON nodes(scan_id, size DESC);
CREATE INDEX idx_nodes_scan_path   ON nodes(scan_id, path);

SQLite: local, embebido, ACID y sin servidor. PostgreSQL solo si se necesita multiusuario.

Cierre

Lo logrado, lo que falta y lo que sigue

Lo logrado

Producto funcional, visual y seguro. Escaneo de discos completos, treemap, lista, búsqueda, filtros y gestión de archivos.

Limitaciones

Sin historial persistente, sin detección de duplicados y escaneo secuencial. La base de datos queda para la siguiente versión.

Trabajo futuro

SQLite para historial, worker threads, detección de duplicados por hash, instalador de un clic y pruebas automatizadas.

DiskMap no solo muestra el disco: ayuda a decidir qué hacer con él.
